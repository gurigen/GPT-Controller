# 4.1.0rc2 の差分と検証範囲

作成日：2026年9月8日。この配布物は公開上流へ反映していない候補版です。前回ZIPの説明ではなく、ソースのハッシュ照合と新しい実行記録を根拠にします。

## 起動直後の端末情報公開

`ControlPoller.last_published=0.0` を未公開状態 `None` に変更しました。以前はOS起動後の単調増加時計が300秒未満の場合、最初のmanifest公開も抑止されました。初回は直ちに公開を試み、失敗した場合は次回の取得時に再試行します。成功してから設定された公開間隔を測ります。

一時的な実Gitリポジトリを使用し、時計を45秒に固定して初回公開を検証しています。公開失敗後の再試行と、成功後の公開頻度制限も別の試験で確認します。処理命令の再実行とは別の機能です。

## 保存成果物の検証

SQLiteの検索用列だけで保存期限や成果物IDを信頼しないようにしました。暗号認証されたメタデータと、取得対象ID・バイト数・期限を一致させ、認証された期限も検査します。暗号文が改変されたHTTP要求には404を返し、例外で接続だけが切れる状態を防ぎます。

これはローカルDBを完全な隔離環境にする変更ではありません。同じOSアカウントを侵害された場合の完全防御、削除済み記録の復旧、任意の秘密情報の自動検出は保証しません。検索用の期限列を短縮して成果物を消すような可用性への攻撃も、この変更だけでは防げません。

## 検証記録

`scripts/run-verification.py` と `scripts/verification_events.py` を実装しました。実行ごとに新しい保存場所を作り、開始時点で最終状態を「実行中」に更新します。全テストの識別名を収集し、各ファイルを別プロセスで実行します。試験失敗、収集失敗、子プロセスの異常終了、時間切れがあっても、残りのファイルを試みます。

各テストの準備・本体・終了処理、JUnit件数、収集した識別名を照合します。欠落、重複、未完了、テスト中のソース変更があれば全体を合格にしません。対象外の試験は合格数へ入れません。最新状態は `verification-local/status.json`、実行単位の生記録はそのrun_directoryです。強制終了・電源断で終了処理が走らなくても、過去の合格が最新状態として残らないよう開始時に更新します。

この記録はテストコードを変更できる悪意ある利用者に対する第三者認証ではありません。同じ出力先への複数の検証プロセスの同時起動はサポート対象外です。

候補準備用のPowerShellも新しい検証処理を呼び、対象範囲の照合・ソースの同一性・対象外ゼロを要求するよう変更しました。この導入処理はコードと静的試験で確認していますが、Windowsで候補を準備・切替・復元する一連の受入は未実行です。
